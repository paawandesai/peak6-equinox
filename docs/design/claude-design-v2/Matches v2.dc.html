Matches: build notes

Template: matches.html. One row per pair. Within each group, rows are sorted by review priority.

Components
  • counter strip, now with a Flagged cell
  • filter chips (a.chip-filter; filter state lives in the URL query)
  • relationship badge, confidence, basis-risk word
  • check strip (ul.checks)
  • freshness badge
  • review flag
VM fields (data already stored)
  • BasisRisk and its word on each row
  • Checks: date, strike, direction and source, from the stored DiffRows
  • ReviewPriority: from type, confidence margin to 0.90 and veto count
  • max quote age per pair, from the round's quote FetchedAt
  • the sort, min and q query params
◆ Needs new data
  • Net and apparent gap per pair: a fee-adjusted price difference. The server does not compute this for matches today.
  • Review flag and the Flagged count, which depend on that gap
  • Fee estimates in the key, which need a documented fee schedule per venue

Until these exist, leave out the Market gap line and the flag. Sorting by review priority still works without them.
