## M2-01: Fed/macro normaliser

**Context:** The M1 demo pair is Fed: Polymarket "increase 25+ bps after Oct meeting" ≡ Kalshi "upper bound above 4.25% after Oct 28" given a fact. Crypto already works; Fed extraction must distinguish meeting date, level vs change (bps), and upper-bound ladders vs change buckets ([domain.md](../domain.md)).

**Satisfies:** FR-06 (Fed/macro)

**Acceptance criteria**
- [ ] `internal/normalize/fed.go` implements `extractFed`. It parses subject (Fed / FOMC / federal funds rate aliases), metric (`rate_upper_bound` vs `rate_change`), comparator, threshold (percent or bps; normalise to a single unit documented in code), deadline (meeting / announcement date + timezone from rules, else close time with `deadline_defaulted`), and resolution source (federalreserve.gov / FOMC statement aliases, else `unknown`). Unparsed fields are `unknown`.
- [ ] `extract.go` dispatches via a small per-category registry (`Register(category, fn)` called from `init` in `fed.go` / later `politics.go`) so M2-02 never edits `extract.go`. Crypto keeps working through the same registry (move the crypto call into `crypto.go`'s `init`).
- [ ] Table-driven tests cover: level vs change, bps vs percent, meeting-date extraction, at least 3 true-parse fixtures drawn from recorded KXFED / fed-rates titles+rules, and adversarial unknowns (ambiguous text → `unknown`, never a guess).
- [ ] Property tests for bps/percent and date parsing round-trips where applicable.
- [ ] If live series/tag names differ from `config/universe/*.yaml`, correct them (Tier 1, logged). Do not expand politics here.

**Verification:** `go test ./internal/normalize/... -run 'Fed|Registry' -v && make cover`

**Dependencies:** none (M1 complete)
**Files likely touched:** `internal/normalize/{extract.go,crypto.go,fed.go,*_test.go}`, `testdata/normalize/fed_*.yaml` (optional), `docs/decisions.md` / `docs/log.md` if universe facts change

## M2-04: Matcher v1 — remaining vetoes, full types, facts, basis risk

**Context:** M1 matcher emits only `equivalent` / `related` / `unrelated` with subject/threshold/deadline vetoes (crypto-exact deadlines). M2 needs polarity + resolution-source vetoes, `equivalent_given_facts` / `complement` / `implies` / `related`, fact application, and basis-risk scoring. This ticket owns all of `internal/match`.

**Satisfies:** FR-08 (all vetoes), FR-09 (all types), FR-11, FR-17 (persist facts_used + basis_risk), NFR-06 (partial — veto suite 0 FP)

**Acceptance criteria**
- [ ] Hard vetoes include polarity and resolution source (in addition to subject / comparator / threshold / deadline). Crypto keeps the D-060 exact-deadline rule unless a Tier 2 entry revisits it. Resolution-source "documented-identical" pairs may be listed in facts or a small allowlist file referenced by facts — **do not silently treat CF Benchmarks ≡ Binance**; if Q-4 option (b) is implemented, log a Tier 2 `D-` entry and show the documentation in the pair diff.
- [ ] Classification produces `equivalent`, `equivalent_given_facts` (when facts close a documented gap), `complement`, `implies`, `related`, `unrelated` per [domain.md](../domain.md). Confidence rules stay conservative and documented in comments.
- [ ] `Compare(a, b, facts.Set)` signature matches architecture.md. Every fact used appears in `Relationship.FactsUsed` / persisted `facts_used`.
- [ ] `internal/match/basis.go` scores basis risk from documented components (cutoff gap, source difference, edge-case rule difference) into `canonical.BasisRisk`; persisted on the relationship.
- [ ] Veto suite extended: polarity flip, source mismatch, complement and implies positive cases, Fed fact-closed pair (the plan demo), December-bucket near-miss as `related`. **0 false-positive `equivalent`** on the veto suite.
- [ ] `equinox match` stores the new types and near-misses per existing D-061 defaults; decision-log explanations name deciding fields and facts.
- [ ] Import discipline: `internal/match` may import `canonical`, `facts`, decimal, stdlib — not venues or web.

**Verification:** `go test ./internal/match/... ./internal/normalize/... -run 'Veto|Classif|Basis|Fed|Complement|Implies' -v && make cover`

**Dependencies:** M2-01, M2-03 (M2-02 strongly preferred before claiming politics pairs)
**Files likely touched:** `internal/match/**`, `cmd/equinox/match.go` (if CLI summary needs new types), `testdata/match/**`, `docs/decisions.md` (Q-4 source-equivalence if acted on), `docs/log.md`
