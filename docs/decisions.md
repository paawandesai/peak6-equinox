**D-056 · operator · Tier 2 · 2026-10-06** · **Decision:** M1-04 Kalshi adapter details, verified against the live public API on 2026-10-06. (1) **Endpoint facts corrected in architecture.md** (the Tier 2 shared-file part): the order book is `orderbook_fp.yes_dollars` / `no_dollars`, each a list of `[price, size]` string pairs sorted lowest price first, so the adapter sorts best first and merges duplicate prices; open markets have status `active` and settled ones `finalized`; settled markets carry `result` and `settlement_ts`. The universe series (`KXBTCD`, `KXETHD`, `KXFED`) are all correct, so `config/universe/kalshi.yaml` only gains a verified note. No live market in these series has a non-empty `mve_collection_ticker`, so the MVE filter is tested on synthetic data. (2) `FetchSettled` sends `since` as `min_close_ts=<unix seconds>` (the API accepts it with `status=settled`; settled lists are newest first, and one day of `KXBTCD` alone is about 4,500 markets). Pages are `limit=200`, capped at 20 event pages and 3 settled pages per series; a repeated cursor is an error. Because the endpoint includes `since`, the fixture server (M1-06) can't compute settled fixture names from the current time; it should match on the path and series, or the recorded `min_close_ts` values (in `internal/venues/kalshi/fixture_test.go`). (3) Kalshi answers bursts with 429 and no `Retry-After` header (about 5–25% of requests at 2–10 req/s from the operator host). The adapter keeps the ticket's 2 retries but uses a 1 s base backoff (1 s, 2 s), and paces every request ≥ 100 ms apart across goroutines (`MinInterval`); `FetchQuotes` runs 4 books at a time. Some requests can still fail after 3 attempts under load, so a full round over ~950 markets takes about 100 s of book fetches. M1-06 should quote only the instruments it needs, or a later ticket can switch to the batch endpoint `GET /markets/orderbooks?tickers=…` (it exists, but its parameter format is unverified). (4) Malformed data: a market with no or an invalid ticker, no title, or a JSON shape that doesn't decode is dropped and logged, and its sibling markets in the same event get a `record_skipped` flag, since a dropped record has nowhere to carry a flag itself. A bad book level (unparseable or NaN price, price outside [0,1], size ≤ 0, an exponent, or a sign) is dropped with an `invalid_price` / `invalid_size` / `record_skipped` flag on the quote. A book that can't be fetched or decoded, or is empty on both sides, gives a quote flagged `no_book`. `FetchQuotes` errors only if the context ends or every book failed. A series that fails is logged and joined into the error while the other series still return. (5) The parsers accept only plain decimals (`^[0-9]{1,6}(\.[0-9]{1,8})?$` for prices, `{1,15}` integer digits for sizes), so `NaN`, `Inf`, exponents such as `1e999999999` and signs never reach `decimal`. Titles are capped at 1,000 bytes and rules at 20,000 (flag `text_truncated`), and NUL bytes are removed. Redirects to another host are refused. (6) Title is `title — yes_sub_title` (the subtitle is skipped if the title already contains it), and rules are `rules_primary` + a blank line + `rules_secondary`. The fee schedule is `kalshi_taker_v1` with `multiplier` 0.07, unverified (M1-07 verifies it). (7) Fixtures: two `record-fixtures` runs on 2026-10-06, the full universe (`-books 6 -settled-days 1`) and a KXFED-only universe (`-books 6 -settled-days 90`, so KXFED has both books and settled markets).
