**D-056 · operator · Tier 2 · 2026-10-06** · **Decision:** M1-04 Kalshi adapter details, verified against the live public API on 2026-10-06. (1) **Endpoint facts corrected in architecture.md** (the Tier 2 shared-file part): the order book is `orderbook_fp.yes_dollars` / `no_dollars`, each a list of `[price, size]` string pairs sorted lowest price first, so the adapter sorts best first and merges duplicate prices; open markets have status `active` and settled ones `finalized`; settled markets carry `result` and `settlement_ts`. The universe series (`KXBTCD`, `KXETHD`, `KXFED`) are all correct, so `config/universe/kalshi.yaml` only gains a verified note. No live market in these series has a non-empty `mve_collection_ticker`, so the MVE filter is tested on synthetic data. (2) `FetchSettled` sends `since` as `min_close_ts=<unix seconds>` (the API accepts it with `status=settled`; settled lists are newest first, and one day of `KXBTCD` alone is about 4,500 markets). Pages are `limit=200`, capped at 20 event pages and 3 settled pages per series; a repeated cursor is an error. Because the endpoint includes `since`, the fixture server (M1-06) can't compute settled fixture names from the current time; it should match on the path and series, or the recorded `min_close_ts` values (in `internal/venues/kalshi/fixture_test.go`). (3) Kalshi answers bursts with 429 and no `Retry-After` header (about 5–25% of requests at 2–10 req/s from the operator host). The adapter keeps the ticket's 2 retries but uses a 1 s base backoff (1 s, 2 s), and paces every request ≥ 100 ms apart across goroutines (`MinInterval`); `FetchQuotes` runs 4 books at a time. Some requests can still fail after 3 attempts under load, so a full round over ~950 markets takes about 100 s of book fetches. M1-06 should quote only the instruments it needs, or a later ticket can switch to the batch endpoint `GET /markets/orderbooks?tickers=…` (it exists, but its parameter format is unverified). (4) Malformed data: a market with no or an invalid ticker, no title, or a JSON shape that doesn't decode is dropped and logged, and its sibling markets in the same event get a `record_skipped` flag, since a dropped record has nowhere to carry a flag itself. A bad book level (unparseable or NaN price, price outside [0,1], size ≤ 0, an exponent, or a sign) is dropped with an `invalid_price` / `invalid_size` / `record_skipped` flag on the quote. A book that can't be fetched or decoded, or is empty on both sides, gives a quote flagged `no_book`. `FetchQuotes` errors only if the context ends or every book failed. A series that fails is logged and joined into the error while the other series still return. (5) The parsers accept only plain decimals (`^[0-9]{1,6}(\.[0-9]{1,8})?$` for prices, `{1,15}` integer digits for sizes), so `NaN`, `Inf`, exponents such as `1e999999999` and signs never reach `decimal`. Titles are capped at 1,000 bytes and rules at 20,000 (flag `text_truncated`), and NUL bytes are removed. Redirects to another host are refused. (6) Title is `title — yes_sub_title` (the subtitle is skipped if the title already contains it), and rules are `rules_primary` + a blank line + `rules_secondary`. The fee schedule is `kalshi_taker_v1` with `multiplier` 0.07, unverified (M1-07 verifies it). (7) Fixtures: two `record-fixtures` runs on 2026-10-06, the full universe (`-books 6 -settled-days 1`) and a KXFED-only universe (`-books 6 -settled-days 90`, so KXFED has both books and settled markets). **D-059 · operator · Tier 1 · 2026-10-06** · **Decision:** M1-11 LLM safety harness details. (1) `internal/llm` splits the contract in two: `Verifier` (architecture.md) returns a schema-valid `canonical.LLMVerdict`, and a lower-level `Model` interface returns the model's raw text, so the strict decoder (`Decode`) and the mocks can exercise malformed output; `NewVerifier(Model)` is the reference pipeline `BuildPrompt` → `Model.Complete` → `Decode`, and it never shows the model the rules verdict. (2) Prompt data blocks are `<<<BEGIN:LABEL>>>` … `<<<END:LABEL>>>`; `Sanitize` applies NFKC, drops control/format/private-use/invalid characters (keeping newline and tab), turns line and paragraph separators into newlines, collapses every run of `<` or `>` to one character and deletes angle-bracket look-alikes, then caps at 4,000 characters with a marker, so no venue text can form a delimiter. `PromptVersion` is `v1`. **D-060 · operator · Tier 1 · 2026-10-06** · **Decision:** M1-06 collector, CLI and admin details. (1) **Quote cap and priority.** A round quotes at most 400 instruments per venue (`collector.DefaultMaxQuotesPerVenue`; `equinox ingest -max-quotes N`, `-1` for all). Kalshi paces requests 100 ms apart (D-056), so 955 books would take 95 s and break NFR-02's 60 s; 400 take about 40 s. Instruments are chosen by `collector.SelectForQuotes`: categories take turns (round-robin) so one strike ladder cannot starve another, and within a category the instruments that have not closed come first, soonest close first, then already-closed ones newest first, then unknown close times; ties break on ID. Instruments beyond the cap are stored without a quote and counted as `quotes_not_requested` in the ingest log entry. On the recorded data this rule picks today's KXBTCD ladder and the next Fed meeting on Kalshi, and Polymarket's "above X on October 6, 6PM ET" ladders (the Kalshi-equivalent markets), rather than Gamma's popularity order ("Will Bitcoin hit $150k by …"). `record-fixtures` now picks books with the same rule, so future recordings have books for what a round quotes; the existing Polymarket book fixtures were the first 10 in popularity order and mostly fall outside the quoted set, which M1-10 should fix by recording books for the matched pairs. (2) **Venue status.** A venue is `ok` only when its instrument and quote fetches returned no error and every row stored; an adapter that returns data together with an error (one series or tag failed) keeps its data but is marked failed with the error text, so the round is `partial` and the admin page shows what failed. A round is `ok`, `partial` or `failed` by counting ok venues. Records that fail validation after normalisation, quotes for unstored instruments, and duplicates are rejected with a warning and counted (`instruments_rejected`, `quotes_rejected`); they do not fail the venue. Every raw body is stored, including 4xx/5xx ones. (3) **One round at a time.** `Collector.Run` refuses to overlap (`ErrRoundInProgress`); `POST /admin/ingest` answers 409 with the running round's ID, so Cloud Scheduler and a manual click cannot double the venue load. Round bookkeeping (`FinishRound`, the `ingest` log entry) runs on a context that survives the caller's cancellation, so a cancelled round is still closed as `failed`. (4) **Normaliser seam.** `collector.Options.Normalize` (`func(Instrument) Instrument`) is where M1-07's `normalize.Extract` plugs in (`cmd/equinox/ingest.go` `buildCollector`); until it lands terms stay `unknown` as the adapters return them. (5) **Ingest endpoint.** 200 for `ok`/`partial`, 502 for `failed` (so Scheduler sees a failed round), 500 for an infrastructure error (round row could not be created or closed; details go to the log, not the body), 503 when no collector is configured. A browser form (`Accept: text/html`) is redirected back to `/admin` instead of JSON. The handler extends its write deadline to 5 min because the server's default write timeout (60 s) is shorter than a round. (6) **Admin auth.** User and password are compared as SHA-256 digests with `subtle.ConstantTimeCompare`, both comparisons always run. The lockout is 10 failures per IP in a 10-minute sliding window, answered 429 with `Retry-After` before credentials are checked; a successful login clears the IP. At most 10,000 IPs are tracked; beyond that new IPs are not tracked (fail open with a log line) rather than letting a flood lock out the real admin. In `staging`/`prod` the client IP is the last `X-Forwarded-For` entry (the one Cloud Run's front end appends); elsewhere it is the peer address. Every `/admin/*` path, known or not, goes through auth first and method checks after, so an unauthenticated probe only ever sees 401. The origin check (AB-12) applies to non-GET methods: `Origin` or `Referer` with a host other than the request host gives 403; both absent is allowed because Scheduler and curl send neither and basic auth still applies, while a browser always sends `Origin` on a cross-site POST. (7) **Serve wiring.** `equinox serve` now builds the pool lazily (`pgxpool.New`, no ping), the adapter registry, the universe and the collector at startup; `/healthz` still needs no database, and the admin page says "database unavailable" until the pool connects. The Dockerfile copies `config/` into the image because the universe is read at startup. (8) **Files outside the ticket list:** `internal/store/stats.go` (`DatabaseSize` for the admin page), `internal/web/server.go` (Deps gain Store, Ingester, Now), `cmd/equinox/serve.go` (wiring), `cmd/equinox/record_fixtures.go` (book selection), `Dockerfile`/`.dockerignore` (config), `docs/environment.md` (fixture URLs). **Why:** the ticket fixes the behaviour but not the quote budget, the failure semantics, the overlap guard or the proxy details; each item records what was needed to meet NFR-02, NFR-03 and AB-05/AB-12 with the adapters as they are. **Rejected:** a time budget instead of a count (Kalshi would report every budget-cut round as failed); quoting in the venue's order (Gamma lists long-dated markets first); asynchronous ingest returning 202 (harder to verify from Scheduler and tests); failing closed above the limiter's IP cap (a lockout DoS). **Reverse:** `-max-quotes -1`, or edit `internal/collector/select.go`; the limiter constants are in `internal/web/middleware_auth.go`.
